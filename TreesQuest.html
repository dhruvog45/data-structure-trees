The Basics of Trees

Unlike arrays or linked lists, a tree is a nonlinear hierarchical data structure. It organizes data in a parent-child relationship, allowing for quicker and easier access.

Key Terminologies

  • Node: An entity containing a key/value and pointers to child nodes.
  • Root: The absolute topmost node of a tree. The starting point.
  • Leaf Node (External Node): The nodes at the very end of paths. They have zero children.
  • Internal Node: Any node that has at least one child.
  • Edge: The direct link connecting any two nodes.

Measurements

  • Depth of a Node: Count the edges from the root down to the node.
  • Height of a Node: Count the edges from the node down to its deepest leaf.
  • Height of a Tree: The height of the root node (or the depth of the deepest node).
VALORANT EXAMPLE: Map Callouts on Ascent
Imagine a tree mapping out paths from Defender Spawn.
- Root: Defender Spawn
- Internal Nodes: Mid Courtyard, A Link, B Market
- Leaf Nodes (Dead ends): A Site, B Site, Mid Pizza
The height to A Site is the number of edges (path segments) it takes to rotate there!
ACT 2: Traversals & BST REWARD: +15 RR

Tree Traversals

Traversing means visiting every single node in the tree systematically. For binary trees, we use three main depth-first methods:

  • In-order (Left, Root, Right):
    1. Visit all nodes in left subtree.
    2. Visit the root node.
    3. Visit all nodes in right subtree.
  • Pre-order (Root, Left, Right):
    1. Visit the root node first.
    2. Visit all nodes in left subtree.
    3. Visit all nodes in right subtree.
  • Post-order (Left, Right, Root):
    1. Visit all nodes in left subtree.
    2. Visit all nodes in right subtree.
    3. Visit the root node last.

Binary Search Tree (BST)

A specialized binary tree where the structure itself maintains a sorted order, making searching incredibly fast.

  • The BST Rule: For any given node, its value must be greater than all keys in its left subtree, and smaller than all keys in its right subtree.
  • Because of this rule, an In-order traversal of a BST will always output the nodes in perfectly sorted ascending order!
VALORANT EXAMPLE: Ultimate Points BST
Let's insert Agent ultimate costs into a BST: Killjoy(8), Reyna(6), Jett(7).
- Root: 8 (Killjoy)
- Left Child of 8: 6 (Reyna, since 6 < 8)
- Right Child of 6: 7 (Jett, since 7 > 6 but < 8)

Traversals for this Tree:
- In-order: 6, 7, 8 (Perfectly sorted by cost!)
- Pre-order: 8, 6, 7
- Post-order: 7, 6, 8
ACT 3: Huffman Encoding REWARD: +25 RR

What is Huffman Encoding?

A famous Greedy Algorithm used primarily for lossless data compression. Instead of using fixed-length codes (like 8-bit ASCII) for characters, it uses variable-length encoding.

How It Works

  • Characters that appear most frequently get the shortest codes.
  • Characters that appear rarely get the longest codes.
  • The Prefix Rule: To prevent decoding ambiguity, no assigned code can be a prefix of another code. (e.g., if 'A' is 01, no other character's code can start with 01).

The Two Major Steps

1. Building the Huffman Tree

  • Create a leaf node for each character, containing its frequency.
  • Sort these nodes by increasing frequency.
  • Take the two nodes with the lowest frequencies, and merge them under a new internal node. The new node's frequency is the sum of the two children.
  • Repeat this process until only one single tree remains.

2. Assigning Codes

  • Traverse from the root down to each leaf. Assign a '0' when going left, and a '1' when going right. The path becomes the character's code!
VALORANT EXAMPLE: Compressing Comms
Imagine encoding the callout "DEFUSE". Frequencies: E(2), D(1), F(1), U(1), S(1).
Because 'E' is the most frequent, the algorithm gives it the shortest binary code (e.g., `0`). Less frequent letters like 'D' get longer codes (e.g., `110`).
Prefix Rule in action: Because `0` is taken by 'E', no other letter's code can start with `0`. This ensures the game server decodes your comms without ambiguity!

Understanding Expression Trees

This is a practical application of binary trees to represent mathematical expressions (like `3 + ((5 + 9) * 2)`).

  • Internal Nodes: Always correspond to an operator (like +, -, *, /).
  • Leaf Nodes: Always correspond to an operand (like numbers or variables A, B, C).

Construction Algorithm (Using Postfix Input)

We use a Stack data structure to build the tree from a postfix expression (e.g., `A B C * +`).

  1. Loop through every character in the input expression from left to right.
  2. If it's an Operand (number/variable): Create a node for it and push it onto the stack.
  3. If it's an Operator (+, *, etc.):
    • Pop the top value from the stack (this becomes the Right child).
    • Pop the next value from the stack (this becomes the Left child).
    • Create a new node for the operator, attach the left and right children, and push this new parent node back onto the stack.
  4. Once the loop finishes, the single remaining element in the stack is the root of your complete expression tree!
VALORANT EXAMPLE: Combat Score Calculation
Let's build an expression tree from the postfix input: DMG KILLS * ASSISTS +
1. Push DMG, Push KILLS.
2. Read * : Pop KILLS & DMG. Create a parent * node with left=DMG, right=KILLS. Push this tree back.
3. Push ASSISTS.
4. Read + : Pop ASSISTS and the * tree. Create a parent + node linking them.
Result: A tree evaluating (DMG * KILLS) + ASSISTS!
